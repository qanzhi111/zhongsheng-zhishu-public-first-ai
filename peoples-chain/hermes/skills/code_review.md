# 代码审查技能
# 用于PR代码审查

## 使用场景
当需要审查PR或提供代码审查意见时使用此技能。

## 审查流程

### 1. 基础检查
- [ ] 代码格式符合项目规范
- [ ] 没有明显的语法错误
- [ ] 变量命名清晰
- [ ] 函数职责单一

### 2. 功能检查
- [ ] 代码实现与PR描述一致
- [ ] 没有逻辑错误
- [ ] 边界情况处理正确
- [ ] 错误处理完善

### 3. 安全检查
- [ ] 没有SQL注入风险
- [ ] 没有XSS漏洞
- [ ] 敏感信息未硬编码
- [ ] 权限检查正确

### 4. 为民原则检查
- [ ] 代码不包含歧视性内容
- [ ] 不支持任何形式的垄断
- [ ] 符合开源共享精神

### 5. 测试检查
- [ ] 核心逻辑有测试覆盖
- [ ] 测试用例合理
- [ ] 测试可重复执行

## PR类型判断
```
feat: 新功能开发
fix: Bug修复
docs: 文档更新
refactor: 代码重构（不改变功能）
perf: 性能优化
test: 测试相关
chore: 杂项/构建/工具
deps: 依赖更新
security: 安全相关
```

## 响应模板

### 功能PR审查
```
## 代码审查报告

### 优点
- ✅ [具体优点]

### 建议改进
- [ ] [具体建议]

### 为民原则合规性
- ✅ 通过

### 总体评价
[评价]
```

### Bug修复PR审查
```
## Bug修复审查

### 问题复现
- [ ] 已验证问题存在
- [ ] 修复后问题已解决

### 测试建议
- [ ] 建议添加回归测试

### 风险评估
- [风险等级: 低/中/高]
```

## 关键判断标准
- 代码行数 > 500: 需要详细审查
- 新增依赖: 需要说明用途
- 数据库修改: 需要migration脚本
- API改动: 需要更新文档
