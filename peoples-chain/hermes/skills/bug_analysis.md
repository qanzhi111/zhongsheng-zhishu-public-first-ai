# Bug分析技能
# 用于分析和处理Bug报告

## 使用场景
当收到Bug报告或需要分析问题时使用此技能。

## Bug分析流程

### 1. 信息收集
- 复现步骤是否清晰
- 预期行为 vs 实际行为
- 环境信息（OS、版本等）
- 错误日志/截图

### 2. 问题分类
```
优先级:
- P0: 紧急，影响核心功能，需立即处理
- P1: 高优，影响主要功能，24小时内处理
- P2: 中优，影响次要功能，1周内处理
- P3: 低优，边缘问题，可后续处理

类型:
- 前端Bug
- 后端Bug
- 合约Bug
- 部署Bug
- 安全Bug
```

### 3. 根因分析
- 找到问题的根本原因
- 确定影响范围
- 评估修复复杂度

### 4. 修复建议
- 提供具体的修复方案
- 评估是否需要回滚
- 建议添加测试防止回归

## 响应模板

### Bug确认回复
```
🐛 **Bug已确认**

**问题概述:** [简述]
**严重程度:** [P0/P1/P2/P3]
**分类:** [类型]

**复现验证:**
- [ ] 环境: [环境信息]
- [ ] 步骤: [复现步骤]
- [ ] 结果: [实际行为]

**下一步:**
1. [具体行动]
2. [具体行动]

---
*🤖 众生智枢AI自动分析*
```

### 需要更多信息
```
🐛 **需要更多信息**

为了更好地定位问题，请提供:

1. **复现步骤** - 请提供详细的步骤
2. **环境信息** - 操作系统、版本等
3. **错误日志** - 完整的错误信息
4. **截图** - 如有异常截图

请回复此评论提供信息。
```

## 关键原则
- 第一时间确认收到Bug报告
- 及时更新处理进度
- 修复后验证并通知用户
- 总结经验教训，防止再次发生
